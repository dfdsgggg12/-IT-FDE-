# 多模态Agent现场编排：FDE的新交付能力，教的是“让视觉和语言在同一个现场里对齐”

多模态Agent的课程通常从模型能力讲起：视觉编码器、跨模态对齐、图文联合推理，学生跑通一个“看图说话”的demo就算入门。但FDE在交付现场面对的多模态问题，和课堂里的完全不是一回事。深空之序的刺绣项目给出了一个精确的教训：AI生成的刺绣图案“看起来不错”，老师傅一看却说机器需要剪线、打结700多次。从“生成结果”到“实际能用”，中间隔着的不是模型精度，是**FDE能不能在现场把视觉输出和工艺约束对齐**。多模态Agent的现场编排能力，本质上是把“看”和“做”之间的那条鸿沟，用工程手段填平。

**第一课：多模态的“多”，在交付现场首先意味着“多源约束的冲突”。**

学生在课程项目里做多模态Agent，输入是干净的图片和文本，输出是一段描述或一个分类标签。真实场景里，多模态输入从来不是“给你什么用什么”。南方电网的换流站巡检项目给出了一个可参照的复杂度：无人机、无人巡检车、固定摄像头、设备监测传感器同时产生视频、红外、温度等多维度数据，传统AI算法“既无法实现跨模态语义对齐，更缺乏理解复杂业务规则的能力”。FDE在实战营里要练的第一项能力，是判断**哪些模态的组合在客户的现场条件下是可靠的、哪些是噪声**。刺绣项目里，视觉模型看到的是图案的美观度，但针迹文件需要的是面料张力、针法可行性、剪线次数这些“看不见的约束”。多模态Agent的现场编排，第一步不是让模型看更多，而是让FDE知道**该让模型看什么、不该看什么**。

**第二课：编排的核心决策，是“人在哪个环节介入”而不是“Agent能自动到哪一步”。**

FDE岗位描述里有一条容易被课堂忽略的要求：在需要的地方应用human-in-the-loop、guardrails和fallback机制。多模态场景的特殊性在于，视觉判断的错误往往比文本错误更难被非专家发现。一个刺绣图案“好看但机器做不出来”，一个报关单照片“清晰但关键字段被遮挡”，这些问题在纯文本Agent里不存在，因为文本有明确的字符边界，而视觉的“对”和“可用”之间有一条专家才能看见的线。

深空之序的报关OCR项目给出了一个可量化的交付路径：团队在义乌现场收集零散、模糊的照片和单据，通过现场迭代改进识别能力，最终把多数报关单的制作时间从至少3小时缩短到约5分钟，单份成本从最低约70元降到约10元。这个案例的教学价值在于：**FDE不是把通用多模态模型直接扔到现场，而是在现场找到“模型在哪类单据上会错、错了之后人工怎么兜底、兜底的成本是否可接受”**。学生在设计多模态Agent时，应该被要求画一张**人工介入点图谱**：哪些判断必须由人确认、哪些可以自动通过、人工确认的触发条件是什么、确认的成本是多少。这张图谱的质量，比Agent的准确率更能决定项目能不能验收。

**第三课：现场编排的产出不是“一个Agent”，是“一套可复用的Skill加测试用例”。**

FDE交付和普通项目交付有一个关键区别：一次驻场解决的问题，应该变成下一个客户不用重新驻场就能用的资产。深空之序的芦宇峰对此的表述很直接：收集到的业务资料和操作经验要整理进知识库，解决问题的方法要沉淀为可复用的Skill，并配套覆盖真实场景和客户运行环境的测试用例，避免“开发时没问题，到了客户现场却用不了”。多模态场景的Skill沉淀比纯文本更难，因为视觉输入的变异性远大于文本：同样的报关单，不同拍摄角度、不同光照、不同褶皱程度，识别结果可能完全不同。学生在实战营里应该做一次**多模态Skill的封装练习**：给定一个现场验证过的视觉判断逻辑，把它封装成带输入约束、置信度阈值和降级路径的Skill，并设计一组“故意刁难”的测试用例（模糊照片、遮挡、反光、非标准格式），验证这个Skill在偏离理想条件时还能不能给出可接受的结果。这个练习的训练目标是：**让学生的交付物从“一个能跑的demo”变成“一个别人敢用的组件”**。

从课程设计的角度，多模态Agent现场编排最适合作为FDE实战营中“交付工程化”模块的收尾，放在学生已经做过单模态Agent、并且经历过“模型在测试集上很好但现场翻车”之后。在这之前，他们关心的是“模型能不能看懂”；在这之后，他们关心的是**当模型看不懂的时候，谁在看、看什么、看完了怎么告诉系统**。多模态的“多”在课堂里是能力，在交付现场是责任。FDE的新交付能力，就是在这两者之间画出一条可执行的线。
